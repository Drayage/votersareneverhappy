# 유권자가 너무해 (Voters Are Never Happy)

> 싱글플레이 **덱빌딩 로그라이크**. 도미니언의 카드 구매·덱 순환·엔진 빌딩 재미를 그대로 가져오되,
> 전투 대신 **도시 발전 점수**를 쌓는다. 당신은 시장(市長)이며, 5번의 평가를 통과해야 한다.

이 저장소는 기획 문서를 실제 웹 게임으로 옮긴 **플레이 가능한 v0.2 프로토타입**이다.
데이터 주도 카드 시스템, 5회 평가 전체 루프, 시장 진화, 유물·정책 상점과 반응형 UI를 포함한다.

## 한눈에 보는 게임

| 항목 | 값 |
|------|-----|
| 장르 | 싱글플레이 덱빌딩 로그라이크 |
| 영감 | 도미니언(Dominion) — 단, 전투 없음 |
| 승리 조건 | **5회 평가** 모두 통과 |
| 평가 주기 | **N턴 플레이 → 평가** 를 5회 반복 (프로토타입 구현값 N=8) |
| 핵심 점수 | **도시 발전 점수** |
| 핵심 시스템 | **시장(Supply) 진화** — 덱이 아니라 시장을 육성한다 |
| 빌드 목표 | "관광/산업/과학/문화/복지 도시" 등 **태그 정체성** 구축 |

## 3종 자원 (이 게임의 뼈대)

| 자원 | 생성원 | 용도 | 수명 |
|------|--------|------|------|
| **예산(Budget)** | 재물 카드 | 턴 중 시장 카드 **구매 전용** | 매 턴 리셋 |
| **도시 발전 점수(Score)** | 점수 카드 | **승리 조건**. 8턴 누적→평가 | 평가 주기 누적 |
| **자금(Fund)** | 평가 종료 시 점수 1:1 변환 | **상점 전용**(유물/강화/시장/정책) | 메타 재화 |

> 도시 발전 점수로는 카드를 살 수 없고, 예산으로는 평가를 통과할 수 없으며, 자금은 플레이 중 쓸 수 없다.
> 세 자원의 **분리**가 모든 설계의 출발점이다.

## 플레이 가능한 프로토타입 (웹)

기획을 기반으로 한 **전체 루프 슬라이스**(5평가×8턴 + 시장 진화 + 상점 + 유물)가 구현돼 있다.
TypeScript + Vite + React, 콘텐츠는 엔진과 분리된 JSON.

### v0.2 업그레이드

- 먼저 사용한 같은 태그 카드 수에 따라 보상이 커지는 **연계(comboScore)** 카드 6종
- 평가 목표 `70 → 180 → 420 → 900 → 1800`, 포퓰리즘·부패 상한으로 완화한 난이도 곡선
- 평가 진행도, 예상 점수, 도시 태그 정체성, 연계 미리보기를 보여주는 반응형 시정 대시보드
- 시장 후보 입력 검증과 CI 테스트를 포함한 게임 상태 안전성 강화

### v0.3 업그레이드 (전략 다양성)

- **정산 전용 카드 손패 패널티**: 정산으로만 점수를 내는 사업 카드 17종은 손에서 사용 불가(`deadInHand`).
  점수 카드를 사 모을수록 손패가 둔해지는 덱빌딩 긴장 — `공약 면책 특례` 정책·`책임 면제` 유물이 이제 실효 있음
- **자금 보상 개편**: 통과 시 `finalScore` 전액 → **목표 달성률 기반**으로.
  턱걸이 통과도 목표의 100%를 받고, 초과분은 절반 비율로만 얹어 목표×1.5에서 캡(오버킬 스노볼 방지)
- **리사이클 카드 3종**: 이번 턴 낸 카드를 덱 위로 되돌리는 `야근 행정`(행정 B)·`앙코르 무대`(문화 A)·`순환선`(교통 S).
  같은 턴 재사용 루프를 열어 압축·회전(싸이클) 덱의 후반 스케일 경로 마련 — 액션 소모형이라 턴당 액션 상한이 자연 제동

### v0.4 콘텐츠 팩 (전략 다양성 2탄)

- **회전 정산 축 신설(`settlementPerPlays`)**: 보유 수가 아니라 **이번 주기에 낸 카드 수**로 정산.
  `시정 활동 보고서`(행정 A)·`순회 축제`(문화/관광 S)·`전국 순회 유세`(포퓰리즘 S) — 회전덱은 돌린 만큼 정산을 받는다
- **주기 점수 배수(`cycleScoreMult`)**: 플레이로 쌓은 점수에만 곱하는 유물 `거리 무대`(+15%)·`라이브 시티`(×1.5) — 과학의 정산 배수와 대칭 축
- **트리거 상한 확장(`extraTriggerCap`)**: `전속 리포터` 유물(+3회)·`시정 방송국` 정책(+2회)으로 지속 트리거 덱의 후반 스케일
- **얇은 태그 보강 17종**: 정치(공청회·개혁 법안), 주거(마을 공동체·재개발 조합), 교육(병설 유치원·장학 재단·평생학습 기금),
  교통(심야 셔틀), 관광(시티투어 버스), 포퓰리즘 A/B 중간 지대(번개 유세·가두 연설·공약 발표회) 등
- **2차 평가 목표 180→160**: 플레이형 덱의 엔진 완성 시점을 고려한 완충 (아키타입 시뮬레이션 검증)
- **트리거 규칙 개편(v0.4.1)**: ① 재물 플레이는 트리거 미발동 — 액션이 안 드는 공짜 플레이가 공짜 트리거가
  되던 잡식 덱의 허점 차단. ② 턴당 공유 상한(6회) → **소스당 상한** — 트리거를 모을수록 총 여지가
  커져 전문화가 보상받는 구조로. `전속 리포터`/`시정 방송국`은 소스당 +2/+1회로 재정의
- **트리거 다타수·저화력 + (지속) 카드(v0.4.2)**: 소스당 상한 3→6회로 올리고 고점 트리거를 3점→2점으로 —
  트리거는 "잘게 여러 번"이 정체성. 새 키워드 **(지속 N턴)**: 낸 카드가 N턴 동안 플레이 영역에 남아
  다음 턴에도 발동 — `먹자골목`(관광/상업)·`대극장`(문화)·`환승 관제센터`(행정/교통, 회전덱 최초의 트리거 지원)
- **과학 배수 개편(v0.4.2)**: 보유 수 × 소스별 곱연산 → **이번 주기에 낸 과학 카드 수 × 소스 가산 합**.
  과학 카드를 사 모으기만 하는 잡식 덱의 배수 무임승차 차단(시뮬레이션: 잡식 오버킬 28283→3470) —
  배수는 과학을 실제로 굴리는 덱만 도달

```bash
npm install
npm run dev        # 브라우저에서 플레이
npm run test       # 엔진/정산/캡/시뮬레이션 검증 (vitest)
npm run build      # 타입체크 + 프로덕션 번들
```

### 구조

| 경로 | 역할 |
|------|------|
| `data/cards.json` · `relics.json` · `policies.json` | **콘텐츠(DB)** — 엔진과 완전 분리 |
| `src/engine/` | 순수 TS 엔진(상태머신·정산·시장·효과 레지스트리·안전장치) |
| `src/content/` | zod 스키마 검증 + 로더 |
| `src/store/` · `src/ui/` | zustand 스토어 + React UI |
| `tests/` | 정산/캡/시뮬/확장성 테스트 |

### 카드·유물 추가가 쉬운 이유 (데이터 주도)

효과는 `{ kind, ...params }` 객체 배열이고, 엔진의 **effect kind 레지스트리**가 종류별 처리를 담당한다.
**기존 kind만 쓰는 새 카드/유물은 `data/*.json`에 한 항목 추가하는 것만으로 코드 수정 없이 동작**한다
(검증: `tests/extensibility.test.ts`). 새 메커니즘이 필요할 때만 `src/engine/types.ts`의 `Effect` 유니온과
`src/content/schema.ts`, 그리고 해당 핸들러 한 곳에 `kind`를 추가하면 된다.

표 스키마(`이름·타입·태그·비용·효과·역할`)는 곧 데이터 명세이므로, 기획 문서의 표를 그대로 JSON으로 옮길 수 있다.
